# Мапінг геймпада для керування рукою (arm gamepad teleop)

> Для ground station: точний перелік осей/кнопок геймпада, які використовує
> `gamepad_servo_node` (`src/arm/arm_teleop/arm_teleop/keyboard_servo_node.py`,
> клас `GamepadInputLoop`) для ручного керування рукою. Запускається через
> `src/arm/arm_teleop/launch/gamepad.launch.py`.
>
> Індекси відповідають **канонічному SDL GameController мапінгу**
> (`joy/game_controller_node`, а не сирий `joy_node`) — тобто той самий
> індекс відповідає тій самій фізичній кнопці незалежно від конкретного
> пристрою/ОС/Bluetooth-стеку. Це навмисний вибір саме тому, що сирий
> `joy_node`-layout "плаває" між пристроями.

## 1. Осі (axes[])

| Індекс | Фізична вісь | Дія (звичайний режим) | Дія (утримано R1/shift) |
|---|---|---|---|
| `axes[0]` | Лівий стік, вліво/вправо | рух вліво/вправо (view Y) | те саме (не змінюється) |
| `axes[1]` | Лівий стік, вперед/назад | рух вперед/назад (view X) | те саме (не змінюється) |
| `axes[2]` | Правий стік, вліво/вправо | yaw інструменту (з інверсією знаку) | roll інструменту (з інверсією знаку) |
| `axes[3]` | Правий стік, вгору/вниз | рух вгору/вниз (view Z, інверсія: вгору стіком = вгору рукою) | pitch інструменту |
| `axes[4]` | Лівий тригер (L2/LT) | **не використовується** для керування — тільки калібрування "нульової точки" тригера при старті | — |
| `axes[5]` | Правий тригер (R2/RT) | **не використовується** — те саме | — |

Рух через лівий/правий стік — у системі координат **камери** (view-relative), а не рами кріплення руки: оператор дивиться через камеру, тому "вперед" повинно відповідати тому, що видно на екрані.

## 2. Кнопки (buttons[])

| Індекс | Фізична кнопка (SDL) | Назва в коді | Дія | Тип спрацювання |
|---|---|---|---|---|
| `buttons[0]` | **A** | `BUTTON_SAFE_POSE` | Планований (collision-checked) рух у безпечну домашню позу + запуск Servo | по натисканню (rising edge) |
| `buttons[1]` | **B** | `BUTTON_SAMPLING_HOME` | Примусово вмикає sampling-режим і одразу веде руку в `sampling_home`. Працює лише коли на руці змонтовано `drill_sampling` інструмент (параметр `end_effector`) | по натисканню, one-shot (не тумблер — вимкнути назад можна тільки перезапуском з іншим `end_effector`) |
| `buttons[2]` | **X** | `BUTTON_EXIT` | Вихід з програми teleop | по натисканню |
| `buttons[3]` | **Y** | `BUTTON_DRILL_HOME` | Примусово вмикає drill-режим і веде руку в `drill_home`. Теж лише для `end_effector == 'drill_sampling'` | по натисканню, one-shot |
| `buttons[4]` | BACK/SELECT | — | не використовується | — |
| `buttons[5]` | GUIDE (логотип) | — | не використовується | — |
| `buttons[6]` | START (номінально) | `BUTTON_LEVEL` | **Пропущено — не налаштовувати.** Індекс не перевірений на реальному контролері, наразі не призначається на ground station | — |
| `buttons[7]` | Лівий стік як кнопка (L3) | — | не використовується | — |
| `buttons[8]` | Правий стік як кнопка (R3) | — | не використовується | — |
| `buttons[9]` | **LB / L1 (LEFTSHOULDER)** | `BUTTON_PUSH_BOOST` | "Push boost" — поки утримано, лінійна й кутова швидкість руки множиться на **×3** | утримання (не edge) |
| `buttons[10]` | **RB / R1 (RIGHTSHOULDER)** | shift-кнопка (без окремої константи; параметр ROS `gamepad_shift_button`, дефолт = 10) | Утримання перемикає роль правого стіка: замість вгору/вниз+yaw → pitch+roll (див. таблицю режимів нижче) | утримання (модифікатор) |
| `buttons[11]` | **D-Pad вгору (DPAD_UP)** | `BUTTON_GRIPPER_OPEN` | **jaw**: відкрити захват (CAN `SAFE_OPEN`). **drill_sampling**: клешня OPEN у sampling-режимі, або дриль UP (реверс) у drill-режимі | по натисканню, one-shot |
| `buttons[12]` | **D-Pad вниз (DPAD_DOWN)** | `BUTTON_LOCK` | **drill_sampling**: замкнути електрозамок (CAN `LOCK`). Немає ефекту для jaw/astrobio | по натисканню, one-shot |
| `buttons[13]` | **D-Pad вліво (DPAD_LEFT)** | `BUTTON_GRIPPER_CLOSE` | **jaw**: закрити захват (CAN `SAFE_CLOSE`). **drill_sampling**: клешня CLOSE у sampling-режимі, або дриль DOWN (вперед) у drill-режимі | по натисканню, one-shot |
| `buttons[14]` | **D-Pad вправо (DPAD_RIGHT)** | `BUTTON_UNLOCK` | **drill_sampling**: розімкнути електрозамок (CAN `UNLOCK`). Немає ефекту для jaw/astrobio | по натисканню, one-shot |

Кнопки 11/13 (D-Pad вгору/вліво) раніше були тумблерами sampling/drill режиму — це перенесено на B/Y, а звільнені індекси віддали дії "open/close"-типу на змонтованому інструменті. Яка саме дія виконується на 11/13, залежить від параметра `end_effector` та поточного режиму (`_sampling_mode`/`_drill_mode`):

| `end_effector` | Режим | `buttons[11]` | `buttons[13]` |
|---|---|---|---|
| `jaw` | — | Відкрити захват (`EndEffectorClient.send('open')`) | Закрити захват (`EndEffectorClient.send('close')`) |
| `drill_sampling` | sampling (за замовчуванням, або після B) | Клешня OPEN (`EndEffectorClient.send('open')`) | Клешня CLOSE (`EndEffectorClient.send('close')`) |
| `drill_sampling` | drill (після Y) | Дриль UP/реверс (`EndEffectorClient.send('drill_up')`) | Дриль DOWN/вперед (`EndEffectorClient.send('drill_down')`) |

Кнопки 12/14 (D-Pad вниз/вправо) — електрозамок drill_sampling-інструмента (`EndEffectorClient.send('lock'/'unlock')`), незалежно від sampling/drill підрежиму. Порядок LOCK=12/UNLOCK=14 обрано довільно (просто дві сусідні вільні кнопки D-Pad) — легко поміняти місцями, якщо оператору зручніше навпаки.

`GamepadInputLoop` більше не відкриває CAN-сокет напряму: `EndEffectorClient` (єдиний клієнт для обох інструментів) публікує одноразові команди в топік `end_effector_controller/command` (`std_msgs/String`) і читає стан з `end_effector_controller/state`. Реальний CAN-лінк живе окремо, в плейн-вузлі `arm_peripherals/end_effector_can_node.py` (той самий патерн, що й `rover_peripherals`'ів вузол освітлення), який і резолвить, що саме означає `open`/`close` для змонтованого інструмента (`jaw` чи `drill_sampling`) — тому `gamepad_servo_node` більше не має параметра `gripper_can_iface` і може працювати на іншій машині, ніж `arm_bringup/arm.launch.py`.

### Підсумок: які кнопки налаштовувати на ground station

| Кнопка | Функція |
|---|---|
| A (0) | Home + start servo |
| B (1) | Sampling home |
| X (2) | Exit |
| Y (3) | Drill home |
| LB / L1 (9) | Push boost (утримання) |
| RB / R1 (10) | Shift-модифікатор правого стіка (утримання) |
| D-Pad вгору (11) | Захват OPEN / клешня OPEN / дриль UP — залежно від інструмента й режиму |
| D-Pad вниз (12) | Електрозамок LOCK (лише drill_sampling) |
| D-Pad вліво (13) | Захват CLOSE / клешня CLOSE / дриль DOWN — залежно від інструмента й режиму |
| D-Pad вправо (14) | Електрозамок UNLOCK (лише drill_sampling) |
| Лівий стік (осі 0/1) | Трансляція вліво/вправо, вперед/назад |
| Правий стік (осі 2/3) | Yaw / вгору-вниз (звичайний режим), pitch/roll (з утриманим RB) |

Кнопку **6 (START, `BUTTON_LEVEL`) не налаштовувати** — індекс не підтверджений на реальному контролері, функція наразі не використовується на ground station. Решта кнопок (BACK/SELECT (4), GUIDE (5), L3 (7), R3 (8)) також вільні — код на них не реагує.

## 3. Режими правого стіка (mode switching)

Один і той самий правий/лівий стік виконує різні дії залежно від активного режиму. Режими взаємовиключні.

### Звичайний режим (не sampling, не drill, R1 не тримається)
| Вхід | Дія |
|---|---|
| Лівий стік вліво/вправо | вліво/вправо (view Y) |
| Лівий стік вперед/назад | вперед/назад (view X) |
| Правий стік вгору/вниз | вгору/вниз (view Z) |
| Правий стік вліво/вправо | yaw інструменту |

### Утримано R1 (shift)
| Вхід | Дія |
|---|---|
| Лівий стік вліво/вправо | вліво/вправо (view Y) — без змін |
| Лівий стік вперед/назад | вперед/назад (view X) — без змін |
| Правий стік вгору/вниз | pitch інструменту |
| Правий стік вліво/вправо | roll інструменту |

### Sampling mode (увімкнено кнопкою B, лише при `end_effector == 'drill_sampling'`)
Pitch і yaw апаратно заблоковані (автовирівнювання), стіки на них не впливають.
| Вхід | Дія |
|---|---|
| Лівий стік вперед/назад | вперед/назад (view X) — без змін |
| Лівий стік вліво/вправо | roll інструменту (інвертовано) |
| Правий стік вгору/вниз | вліво/вправо (view Y), інвертовано |
| Правий стік вліво/вправо | вгору/вниз (view Z), інвертовано |

### Drill mode (увімкнено кнопкою Y, лише при `end_effector == 'drill_sampling'`)
Pitch і yaw заблоковані так само; roll відсутній повністю (керування orientation тільки автоматичне).
| Вхід | Дія |
|---|---|
| Правий стік вліво/вправо | вперед/назад (view X), інвертовано |
| Правий стік вгору/вниз | вліво/вправо (view Y), інвертовано |
| Лівий стік вперед/назад | вгору/вниз (view Z) |
| Лівий стік вліво/вправо | **не використовується** |

R1/shift ігнорується в sampling і drill режимах.

## 4. Параметри чутливості / deadzone / тайминги

| Параметр | Значення | Опис |
|---|---|---|
| Deadzone стіків/тригерів | `0.2` | Застосовується вручну в коді (`GamepadInputLoop._DEADZONE`); deadzone самого `game_controller_node` навмисно виставлено в `0.0` в launch-файлі, бо ненульовий драйверний deadzone змушує вузол взагалі переставати публікувати `/joy`, коли стік у спокої |
| Базова лінійна швидкість | `0.6` м/с | Множиться на значення осі; помножується на push-boost |
| Базова кутова швидкість | `1.8` рад/с | Те саме для pitch/yaw/roll |
| Push-boost множник (LB/L1) | `×3.0` | Діє, поки утримано `buttons[9]` |
| Таймаут `/joy` | `0.2` с | Якщо повідомлення з геймпада не приходять довше — рука зупиняється |

## 5. Кінцевий інструмент (end effector) — окремий CAN-канал

Кнопки 11/12/13/14 шлють одноразові команди на топік `end_effector_controller/command`, а не через сервоконтур руки. Спрацьовують по натисканню (не по утриманню). Сам CAN живе в окремому вузлі, `arm_peripherals/end_effector_can_node.py` (не в `keyboard_servo_node.py`), який транслює ці команди в проводовий протокол змонтованого інструмента:

- **jaw** (CAN `0x1A`): `SAFE_OPEN`/`SAFE_CLOSE`.
- **drill_sampling** (CAN `0x1E`): `OPEN`(2)/`CLOSE`(1) для клешні, `UP`(5)/`DOWN`(4) для дриля, `LOCK`(7)/`UNLOCK`(8) для електрозамка.

## 6. Відомі розбіжності зі старою документацією

`docs/arm/arm_teleop.md` описує **застарілий** мапінг: тільки базовий режим (без B/Y, без захвату, без push-boost, без level) і вказує дефолтний shift-button = 5, тоді як у коді дефолт — **10**. Цей документ (`arm_gamepad_mapping.md`) відображає поточний стан коду; при розбіжності орієнтуватись на нього і на клас `GamepadInputLoop` у `keyboard_servo_node.py`.
